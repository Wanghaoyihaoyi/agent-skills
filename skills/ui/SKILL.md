# UI

> 来源：基于 [Tw93 / Waza 的 ui 技能](https://github.com/tw93/Waza/tree/main/skills/ui) 改编。保留 Tw93 的 [MIT 版权声明](LICENSE)。

每次使用时，首条进度消息以 `🥷` 开头。仅要求审查时保持只读；已授权实现时完成修改与相应验证。沿用项目的组件、主题、样式和已有授权，不为界面打磨新增依赖或产品流程。

## 先确定界面依据

先看现有组件、主题、间距、圆角、颜色含义、动效及文案；已有成熟设计时直接沿用。用户给出截图、参考页面或旧版本时，对照真实内容，不凭印象还原。

确认使用者、设备和场景：手机、桌面、落地镜或远距离大屏的尺度不同。只问现有证据无法解决的产品或风格选择。小修复直接做；新界面或明确改版先简短说明设计方向和主要操作，不强制生成设计文档或多套方案。

按任务需要读取资料，不一次加载全部：

- 截图反馈、反复改仍不对、状态切换不稳定：[截图与渲染验证](references/mode-screenshot-iteration.md)。
- 新页面、响应式布局、主题或文字体系：[设计细节](references/design-reference.md)。
- 原生界面的动效或按压反馈：[原生动效](references/design-native-motion.md)。
- 数据看板、图表或密集数值：[数据展示](references/design-data-viz.md)。

独立生成或编辑位图使用 `imagegen`；手机网页的滚动、触控和安全区问题可使用 `mobile-native`。两者不是所有 UI 任务的前置步骤。

## 布局与操作

- 先靠间距分组，再考虑底色和分隔线。对齐到少数共享边线，主操作与当前最重要的信息容易找到。
- 一屏或一个任务区保持清楚的操作优先级，按钮和静态文字要能区分。
- 不让键盘、安全区、滚动、长文本或窄屏遮住关键操作；页面能返回，弹层能关闭。
- 触控区域按平台和实际距离选择；没有既有约定时，手机可从 44×44 逻辑单位起步，大屏结合站姿放大。装饰层不吞点击。
- 图标按钮有可访问名称，键盘焦点可见且顺序合理。Web 使用正确语义元素；Flutter 和原生界面使用对应的语义与焦点能力。

## 文字、颜色与动效

- 使用用户听得懂的词；按钮说明动作和结果。同一流程用同一套词，技术错误码放日志。
- 错误就近说明原因与下一步；空状态说明这里是什么、怎么开始。重要内容被截断时可查看全文。
- 字号、字重、行高沿用现有体系。变化中的数字和数值列使用等宽数字，检查中文、长词和字体回退。
- 颜色按语义取用，不能只靠颜色表示状态。实测渲染后的前景与背景对比；发现问题后在已授权设计范围内调整，跨出该范围才确认。
- 动效说明状态变化，不能掩盖等待或替代静态提示。高频操作及时反馈，过渡可打断，减少动态效果设置下仍能看懂状态。
- 不为统一效果给所有按钮加缩放，不无故播放首帧动画，不用一个动画与另一套机制同时控制同一属性。
- 间距或尺寸反复调仍不对时，检查共同容器、字体指标和状态布局的原因，不继续堆独立数值。

## 覆盖实际可达状态

按改动涉及的风险检查正常、加载、空、失败、超时、重试、取消，以及超长文本、缺图、慢网络、权限或设备不可用。检查进入、下一步、退出、返回；异步流程还要看迟到结果和断线恢复。

加载尚未完成不能显示最终“没有结果”；刷新已有内容时明确等待状态。语音界面的屏幕提示和实际播放、收音或任务状态一致；改文案不能代替修复上游行为。

跨状态检查同一操作区的尺寸与基线，避免文字、图标或按钮切换导致跳动。共享组件的问题检查实际受影响的使用处，不扩成无关改版。

## 验证与交付

按项目能力实际渲染，检查相关屏幕尺寸、支持的主题和状态。静态截图只能证明静态外观；按压、滚动、动画和异步反馈需要实际交互或录屏。无法预览时说明缺少的证据，给出最短的复验入口，不把构建通过当作界面验收。

实现后说明哪些界面变化、用户会看到什么、验证了哪些状态；可行时提供前后截图。只读审查给出位置、场景、影响和修改方向，区分本次引入与原有问题。没有值得改的地方就直说。
