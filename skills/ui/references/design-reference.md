# 设计细节

仅在新页面、响应式布局或主题与排版工作需要时使用。已有设计和用户参考优先，以下检查不构成自动改版或新增产品范围的授权。

## 复用与视觉层级

复用已有布局、组件、图标、字体和样式体系。避免两个机制同时控制同一视觉属性；不同技术方案并存并不自动是缺陷，先证明实际冲突。

工作台以定位、状态与操作为主；营销页面围绕真实内容和用户行动组织。不要为显得独特强换字体、添加装饰、预设某种卡片或颜色一定错误。需要方案对比时，变化应体现在布局、信息密度或交互方式，而不只是换强调色。

## 排版与主题

检查真实中文、英文、数字、长名称和字体回退。正文保留自然换行；不要用缩小字号或随意断行掩盖容器问题。按钮、状态区和并列卡片的排版在内容变化时保持稳定。

沿用颜色、圆角、间距和文字语义；嵌套圆角检查实际视觉关系，不机械套公式。图标与文字需要视觉对齐，必要时做有依据的微调。

在产品已支持的明暗主题中实测文字、图标、焦点、错误与禁用状态。对比不足时按项目标准调整，不凭色值猜测。样例数据明确标注，不伪装成真实用户、营收或业务结果。

## 响应式与可访问性

检查内容是否被窄屏、窗口缩小、文字放大、键盘和安全区遮挡。保留键盘操作、焦点顺序、可访问名称、图片替代文本和明确的错误反馈。表单错误靠近字段，返回和关闭操作可用。

Web 图片预留尺寸，避免加载时布局跳动；按实际首屏需求加载字体和图片。性能优化以证据为准，不预先给所有元素加合成层。不要使用 `transition: all`；只动画实际需要变化的属性。

手机网页若涉及滑动、悬停残留或安全区，按需使用 `mobile-native`；这些平台规则不直接套到 Flutter 或原生界面。

## 范围

设计文档、隐私页面、同意流程、404 页面和新的导航入口只在任务或产品要求时增加。能用现有体系完成的局部修改，不新建完整设计系统。

部分可访问性、动效和排版检查整理自原 UI 资料；其来源包括 [Impeccable](https://github.com/pbakaus/impeccable)（Apache 2.0）、[getdesign.md](https://getdesign.md)（MIT）和 [taste-skill](https://github.com/Leonxlnx/taste-skill)。
