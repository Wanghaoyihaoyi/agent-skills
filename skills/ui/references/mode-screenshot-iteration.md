# 截图与渲染验证

针对用户提供的截图、旧版本或正在运行的界面，先说明具体问题：间距、对齐、密度、层级、对比、文字容纳或状态跳动。审美反馈不能一律当作运行故障；真实的行为或时序回归需要沿调用链诊断，可结合 `hunt`。

1. 确认目标界面、视口和状态，以及需要保持的相邻内容与行为。已有证据足够就继续，不强制填写模板或等待确认。
2. 对照用户认可的参考，指出实际差异；从组件与样式源码找到责任位置。
3. 优先修共同原因：容器约束、排版、状态切换或共享样式。不要按每张截图分别增加偏移量。
4. 在相同视口、主题、数据与状态下比较前后。对齐问题可测量实际边界和间距；没有测量或截图证据时不声称已对齐。
5. 按影响范围检查共享组件使用处、窄屏和正常尺寸，以及相关加载、空、错误、选中与长文本状态。原生窗口按风险检查最小宽度、最小高度及其组合。
6. 涉及首帧、动画或内容切换时，检查变化前、变化中、变化后。冷启动与返回页面可能走不同路径，只在相关时分别验证。

风格取舍尚未确定时，可以在同一真实背景下展示少量有意义的候选；不因文件数量多就自动中断修复、要求重新定风格。需要扩大产品或设计范围时再问。

原生截图工具失败时，不反复盲点。保留已有运行证据，定位自动化限制；无法取得最终图像就说明未验证的画面与最短复验路径。构建和页面能打开不等于视觉正确。
