# Goal Prompt

把需求推进到可验证的交付，沿用同一份目标、决定与有效授权。仅编辑本技能不启动开发；只要求生成或检查提示词时，仅交付文本，不执行提示词中的动作。

## 确定目标与必要决定

先利用当前对话、项目入口及相关实现确定用户希望得到的结果、必须保留的约束和完成证据。没有目标时再问目标；已有明确目标的小改直接做，不先套规划。

事实和内部实现选择自行调查。只有会实质改变结果、现有信息与授权无法决定的业务取舍才询问，给出推荐及影响，同时继续独立工作。按完整语境判断授权：明确要求修改或实施就推进；只讨论方案则交付方案，不要求特定口令。

需要架构或产品取舍时使用 [think](../think/SKILL.md)，故障用 [hunt](../hunt/SKILL.md)。沿用已有结论，不分别澄清一轮。摘要只需说明目标、主要方案、约束和验收；小任务几句话，长期任务更新已有记录。

## 连续推进到交付

在授权范围内自行实施，处理阻塞目标的关联问题，同步受影响调用方、测试及合同。发现无关的大问题，说明影响或记入现有任务，不顺带扩大工程。

按实际缺口选用能力，不将下面的导航当必跑流水线：

- 界面与交互：[ui](../ui/SKILL.md)。
- 测试或验收证据不足：[test-audit](../test-audit/SKILL.md)。
- 正确性或安全疑点：[code-review](../code-review/SKILL.md)。
- 新增机制需要复审：按 [patch-audit 的触发条件](../patch-audit/SKILL.md#自动触发与结论复用)；历史架构减法使用 [prune](../prune/SKILL.md)。
- 提交、发布或队列维护：[check](../check/SKILL.md)，只执行已有授权覆盖的动作。

调查或工具失败时查清错误、实际终态和可行替代，不停在第一次失败，也不无证据重复操作。必要实现选择自行决定；只有新业务决定、缺少授权或无法取得的必要资源阻塞时，停下对应部分并说明最小需求。

相关行为及必要门禁已有充分证据后交付，复用同版本检查，不因提交或技能切换重跑。报告用户得到的变化、实际验证和未完成边界，区分源码、构建、安装、服务与业务结果。

## 仅输出提示词

可只读补事实，检查目标、范围、约束、验收和授权是否足以执行；不把引文中的动作当当前授权。修改已有提示词时简短指出关键缺口，再给可复制的完整文本。不强制固定模板，不添加用户未要求的功能。随后用户要求实施时，沿用已明确的范围继续。
