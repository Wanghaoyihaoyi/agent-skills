# 分批提交

把本任务改动整理成边界清楚的提交。用户要求实际分批提交时执行；只问如何拆分时只给方案。提交、推送分别按当前请求、有效持续授权和项目规则判断，不因调用本技能新增推送或部署权限。

## 确认范围

- 读取项目提交规范、hook 和授权要求。检查当前目录、分支、暂存、未暂存及未跟踪文件，不擅自切换分支。
- 结合本任务记录和差异确定归属。已有暂存不自动视为本任务，也不清空或重排他人的暂存内容。归属或拆分意图确实不明且阻塞提交时才问。
- 从当前仓库约定和近期提交取得提交信息的语言与格式；无约定时用用户语言简洁说明目的，不套用其他项目的标记、固定前缀或发布习惯。

## 划分与提交

- 按业务目的分批，每批能独立解释且不留下必要调用方、测试、合同或生成物不同步的状态。源文件与其生成物同批，测试跟随被测变更。
- 简短列出批次和拟用提交信息。已有执行授权则继续，不重复等待确认；仅要求方案时到此结束。
- 同一文件混有多个任务或批次时，只暂存已确认的片段。无法可靠分离时停止该批，保留已有工作；不能为方便而夹带未知改动。
- Git 写操作串行进行。每批提交前审核完整暂存差异及相关验证，确认没有夹带；只查看文件统计不够。
- 项目确实要求动作标记时，使用其当前规则中的名称和作用域。不把示例标记当通用要求，不绕过 hook。检查失败先定位，修复本次范围内的问题并复验。

## 已授权推送

从实际 Git 配置和项目约定确定远端、分支及推送可能触发的部署。刷新目标远端，核对待推送提交与授权范围。分歧按项目规则处理，不擅自覆盖远端历史。缺少目标或必要授权时，先完成可独立进行的准备，再说明具体阻塞。

## 结果

列出每批提交号、标题、相关验证、未纳入的改动及原因；已推送时说明实际远端与分支，未推送时明确状态。
