# 中文公告与发布说明

先匹配用户要求、目标受众、实际渠道和项目已有格式。社区项目、商业产品和内部工具的语气可以不同，以下是选择依据，不是统一模板。

## 公告或社交发文

- 围绕本次真实用户结果选择重点，不照抄完整提交列表，也不凑固定数量的亮点。
- 有实际反馈或社区关系时可感谢贡献者；没有材料就直接说变化，不虚构 star 数、用户评价或个人立场。
- 用受众熟悉的表达解释体验变化，是否使用口语、邀请或行动提示取决于渠道和用户要求。不强制“小伙伴”“玩玩”等语气。
- 区分已上线、预览可用和未来计划，不能把设计或本地实现写成已经发布。

## 发布说明

沿用项目既有格式和语言。无既有格式时，按实际需要组织兼容变化、新能力、修复或弃用，不创建空栏目。只有需要双语时才给双语，保持两版含义对应。

每项说明用户结果；兼容变化、迁移步骤、支持版本和必须执行的操作不能为了简短而删掉。机制细节只有帮助使用者做决定时才保留。

发布说明与社交公告可有不同长度，不强制使用 GitHub、固定标题词数或条目数。维护状态、发布时间、版本和渠道必须有证据；发布文案本身不授权实际发布。
