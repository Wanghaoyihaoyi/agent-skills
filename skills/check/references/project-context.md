# 项目上下文与发布清单

从当前项目规则、README、构建配置、CI 和明确需求取得约束，不把私有记忆或别的项目命令写成通用规则。文档声称存在的门禁须与实际脚本或 CI 对照。

## 按任务取证

| 项目 | 需要的证据 |
|---|---|
| 授权与目标 | 本次动作、目标仓库、分支、账号、环境或渠道；有效持续授权 |
| 比较基线 | 用户指定引用或实际已发布版本，到本次候选提交的范围 |
| 工作区 | 暂存、未暂存、未跟踪及其他任务改动的归属 |
| 远端 | 刷新后的目标引用、待推送提交，不以旧的本地跟踪引用证明同步 |
| 代码与测试 | 当前范围的审查结果、相关命令、实际运行结果与未覆盖边界 |
| 版本与生成物 | 项目要求一致的版本字段、合同、构建输出和发布说明 |
| 包内容 | 实际包内文件、引用、脚本、资源、权限及依赖完整 |
| 安装后行为 | 改动涉及安装路径时，在隔离环境验证真实入口 |
| 渠道与上传 | 预览、正式、包仓库或应用商店；实际资源与目标版本相符 |
| CI 与部署 | 对应提交的检查和服务状态，不能用其他版本的绿灯替代 |
| 业务结果 | 指定设备、供应商或用户流程的真实验收，或明确未验证 |
| 对外条目 | 回复、关闭、合并前后的 issue/PR 身份和实际状态 |

只执行本任务适用的项，缺少对应发布面时记为不适用。普通提交不自动要求构建全部客户端或访问生产。

## 涉及删除、覆盖或权限变化

确认目标能被用户识别、操作范围可核对、部分失败和重试不会扩大影响，必要时使用 dry-run 或隔离验证。不能把“看起来无引用”当作可删除用户数据的证明。

对 CLI 另查参数、退出码、标准输出与错误输出、配置优先级、非交互模式和真实安装路径。方法见 [产物与发布面](release-surfaces.md)。
