# 退役证据与开关清理

方法参考：Rodrigo Roim，OpenAI，[Maintaining software with the GPT-6 family](https://developers.openai.com/blog/maintaining-software-with-the-gpt-6-family)（2026-10-14）。以下为独立整理，适用于 Statsig 或项目实际使用的功能开关、配置与实验平台，不要求接入特定平台。

## 为删除建立证据链

从调用入口和资源用途提出候选，自主选择能核实假设的来源：当前代码、历史 PR、任务记录、已有团队讨论、配置快照、生产调用统计及性能采样。讨论说明意图，当前配置说明取值，调用和采样说明实际执行；单一来源不能自动代替其余证据。只使用任务允许访问的来源；读取讨论不授权发消息，审计不授权改变线上配置、服务或采样设置。缺少来源时写明缺口，不把未接入当成零使用。

生产证据注明时间窗口、环境、运行版本、覆盖人群和采样限制。日志或采样未出现某路径，只能说明在所观测范围未出现；排除观测盲区、低频定时任务、受支持旧客户端及故障恢复用途后，再结合调用链判断。能静态证明不可达的残留不必强求生产遥测；仍可能动态触发的高风险路径，证据不足则保留并指出所需证据。

区分三种情况：没有入口的死代码；仍被求值、但结果已固定的判断；平时不触发、故障时有用的应急能力。默认关闭、100% 上线、长期未变、stale 标签或名称含 legacy 都只是线索。永久开关、紧急关闭、运维覆盖和安全隔离有明确用途时保留；成本高也不自动允许删除。

## 全量开关与实验审计

用户要求全量时，在约定范围内对账两份清单：平台的项目与对象清单，以及代码和部署配置里的实际引用。覆盖 gate、config、experiment、layer 及对象间依赖；没有平台的项目按实际配置机制处理。为每个生产引用给出结论，也检查未被平台标 stale 的对象。无法解析的动态引用列为未核实，不能从清单中消失。

沿枚举、常量、包装函数、别名、schema、动态拼名和跨服务消费者追到真实对象名；反查常量开关是否被其他开关或实验依赖。字符串搜索与 SDK 直接调用扫描不够，删除一处映射前检查它展开出的依赖和求值扇出。

核对线上真实规则和取值，包括适用环境、人群、版本、定向覆盖及关联对象。SDK 默认值和本地 override 不能用来证明线上恒定；它们若承担真实的断网、初始化或兼容行为，替换后仍须保留必要语义。删除求值还可能改变曝光记录、初始化、缓存或其他副作用，不能只验证返回值相同。

结合生产遥测和性能采样检查高频求值、递归依赖与展开扇出的 CPU 成本。注明样本窗口、频率、单次与累计成本的口径；区分实测、估算和未知，不能由无样本写成零成本，也不把整条调用栈的 CPU 都算作可节省量。

## 交付与实施

短任务在已有记录中保留证据即可。全量审计或用户要求报告时，输出 Markdown，按归属与文件工作流分组；每项包含对象名、生产取值、引用位置、证据链接与日期、负责人（未知则标明）、观测或估算成本、保留或删除结论和验证方法。列出未审范围及清单对账缺口，不能只交保守候选短名单。分组用于减少冲突，不自动启动并行代理或向其他聊天派工。

先处理一个证据充分、可独立验证的小批次，再按同样标准扩大；不因报告候选多就一次混合删除。审计请求只交报告；实施已授权时，按业务影响、证据、可测收益和迁移风险排序，清除退役路径专属代码、依赖、配置引用、测试和文档，保留仍有效的合同。线上对象的修改、归档或删除单独遵循适用授权，不能以清理本地代码替代线上变更授权。

验证最终保留的行为与应急、兼容边界；性能、镜像或依赖收益用同条件前后结果说明。删除行数只作规模信息。每批根据实际复审反馈修正下一批的搜索与判据，不把一次漏检固化成永久规则。
