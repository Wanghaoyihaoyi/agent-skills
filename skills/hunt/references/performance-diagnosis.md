# 关键路径与可观测性诊断

用于性能、积压和跨服务卡点。只读诊断不授权改服务、加线上采集、压测或部署；调查证据支持根因后，继续本任务已有授权范围内的修复。

## 固定用户结果与测量边界

分别定义输入结束到有意义反馈、首次实际播放或展示、最终业务完成的时间；界面状态、服务返回、播放确认与持久化不是同一完成信号。记录版本、环境、负载、冷暖启动、缓存、输入规模和测量起止事件，确保前后比较条件一致。

重复测量并报告样本数、分布和失败，不只报平均数。P95、P99 表示较慢请求所在的分位点；小样本或只采成功请求会误导，需说明采样与缺失。延迟、正确性、资源和总调用成本一起看，不能把提前说话、隐藏错误或增加重复模型调用当性能收益。

## 追到真正决定完成时间的路径

用请求、任务及资源归属标识关联客户端、网关、服务、模型和最终效果，记录必要的开始结束、排队、重试、取消与完成确认。跨服务使用实际传播的追踪上下文；Trace 是一次链路的整体记录，Span 是其中一个操作。复用已有工具和 OpenTelemetry 能力，不以“先搭追踪平台”阻塞最小诊断，也不为关联记录泄露用户数据、令牌或完整上下文。

画实际依赖与时间线，区分排队、执行、网络和等待确认；嵌套或并行区间不能简单相加。关键路径决定最终完成时间，单个最慢片段未必在关键路径上。跨机器时钟偏差和不同端的计时起点须说明；单进程耗时优先用单调时钟。

对慢样本按场景、版本和负载分组，找与正常样本不同的路径：队列积压、资源饱和、重试放大、缓存未命中、串行依赖或恢复等待。链路缺一段先补能区分假设的最小观测，不猜缺失阶段的耗时，也不反复重跑同一请求替代负载证据。

修复后以原条件重测端到端结果和受影响失败路径；采用有界并发、背压、流水线或推测执行时，同时确认取消、状态归属和额外成本。只优化非关键路径时，说明局部收益，不宣称最终完成变快。

## 可靠性指标与决策边界

SLI（服务质量指标）要定义测量位置、有效请求分母、成功或超时判据；SLO（服务质量目标）要定义目标值和时间窗口，优先沿用项目已确认目标。服务存活和 HTTP 成功不代替业务成功。错误预算是该窗口内目标允许的失败额度，不是忽略错误的许可；按已有策略决定是否优先稳定性，未确认目标或暂停发布规则时不自行设阈值或冻结发布。

自恢复必须有观测到的故障、受控重试或恢复预算、成功判据和明确失败出口。没有状态证据，不盲目重启、重投有副作用的请求、清数据或旋转凭据。故障注入只在适用授权和隔离条件下进行，可用 `test-audit` 选择恢复验证。
