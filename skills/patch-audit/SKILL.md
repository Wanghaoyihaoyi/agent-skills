# Patch Audit

复审本任务新增机制是否必要，在有效实施授权内简化并验证。只读时仅报告；仅要求等价整理时不顺带改变功能。仅编辑本技能不启动项目复审。

## 自动触发与结论复用

交付前，本轮新增状态协调、重试／兜底／兼容、新依赖或责任边界，出现重复补丁链，或有具体职责混杂、散落特例、重复实现时，才自动复审。用户明确要求时按指定范围执行。

普通局部实现、机械修改、文档和配置值调整、行数增长本身不触发。复用同版本已有必要性结论；拆分提交、重新暂存或 amend 说明不重跑，后续变化仅补审受影响部分。不要将其他技能的导航当额外门禁。

## 确定实际差异

核对目录、分支、Git 状态与本任务归属，不覆盖、回退或暂存他人改动。默认审本任务相对 `HEAD` 的差异及相关未跟踪文件；`--staged` 以暂存区为起点，路径参数限制范围，`--ref=<引用>` 使用指定基线。范围为空就结束，不自动审上一笔提交或全仓。

引用先用 `git rev-parse --verify --end-of-options '<ref>^{commit}'` 验证。读取差异禁用外部 diff 和 textconv，路径正确引用并置于 `--` 后；暂存与工作区交叠时核对版本，保持已有暂存状态，生成物修改源头。

## 判断与收敛

从原始目标、合同、根因和调用链判断，不把刚写的代码或测试当正确性证明。对新增机制回答：它保护哪个真实需求？更直接方案为何不足？维护和同步成本是否值得？

重点查“新增标记 → 补同步 → 加锁或延迟”等补丁链，能否在拥有状态或副作用的边界一次解决。真实外部兼容和安全保障保留；迁就本轮未同步的内部旧调用方则直接同步，删除失效路径。

区分有依据的限定特例与仅匹配报错样例的补丁。必要时换一个真实相邻入口或时序核对同根因是否仍成立，并检查正常行为是否被误伤；不为假想场景建立通用框架。证据不足先调查，不能证明旧保障无用时保留。

职责疑点存在时才看完整文件及关联结构；大小是线索，不设统一行数门槛。抽象应减少真实修改点，搬文件或增加转发层不算简化。

上述结构审查参考 [Cursor 的 Thermo-Nuclear Code Quality Review](https://github.com/cursor/plugins/blob/main/cursor-team-kit/skills/thermo-nuclear-code-quality-review/SKILL.md)，保留其 [MIT 许可证](LICENSE)。

静态证据能回答就不另造实验；机制收益存疑且能建立有效对照时才做隔离消融。覆盖机制要防范的失败，不凭正常路径通过删除保障；不重复真实消费或写入。未运行的对照不称为实验，最终版本仍需相关验证。

发现直接相关的测试、命名或现行说明误导时一并修正，历史记录保留事实与适用边界，不全面巡检文档。需要故障诊断或测试审查时按需使用 [hunt](../hunt/SKILL.md)、[test-audit](../test-audit/SKILL.md)，复用已有证据。无关问题不阻塞交付或扩成全仓治理。

## 验证与交付

修改后验证受影响的正常行为、目标失败和关键保障，检查最终差异与 `git diff --check`。等价简化保留公共合同、副作用顺序和错误语义；修复应能区分原错误与目标行为，不放宽断言迁就实现。

没有修改时复用已有验证，不为流程重复测试。发现影响正确性的问题就在授权内解决，无法解决时说明具体阻塞；通过后继续已授权交付，不新增确认关卡。

简短说明删掉什么、保留什么及依据、验证和未验证部分。没有安全且有价值的简化可以不改，不为显得做了复审制造变更。
