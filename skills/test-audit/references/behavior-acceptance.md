# 专项行为验收

沿用 [test-audit](../SKILL.md) 的独立预期、任务范围、授权和停止条件。只读取与当前风险对应的部分；这里的方法不是每次都要执行的清单。

## 异步任务、语音、模型与设备

分别取得证据，不跨层推断完成：

| 事实 | 能支持的结论与所需证据 |
| --- | --- |
| 请求受理 | 返回值或回执证明受理；accepted、partial 是否算完成服从业务合同，不直接等同 completed。 |
| 业务完成 | 真实处理入口后的终态和业务输出，关联正确的任务、请求、对象与接待或会话。 |
| 结果持久化 | 实际存储中的正确结果；重启恢复还需新实例或进程读取该存储，原实例内存结果不够。 |
| 页面展示 | 用户实际看到的页面与正确结果；服务端成功不证明页面已更新。 |
| 播放请求 | TTS、音频下发或播放命令证明对应请求发出，不证明设备出声。 |
| 实际播放 | 对应目标设备的实际音频或现场观测证据，注明设备、版本与验证条件。 |

- 必要关联缺失时不猜测。旧接待的迟到结果不得进入新接待；同一接待重连后的接续按已有合同验证，不能一律丢弃。
- 重复事件不得产生合同禁止的重复副作用。检查实际写入、任务、扣费或播放效果，不能只确认去重函数被调用。
- 区分取消请求、取消受理和取消已生效；取消与完成的竞态按已有状态机裁决，不新增未经确认的优先级。
- 注入正确 tool call 仅验证其下游；真实模型是否会选对工具，需要实际模型证据。语义等价的自然语言允许通过，核对业务事实，不机械匹配固定话术。
- Web、模拟器与真机分别报告。持久化、真实供应商、模型选择或设备播放缺条件时，继续其他可执行工作，明确尚缺的层级与最小验收步骤。

## 按具体证据缺口补强

所有新增测试仍通过主文件的 Authoring gate，优先复用现有框架、夹具和隔离环境。不因有高级方法就要求安装依赖；下面任何一种通过都不能证明所有输入、时序或环境正确。

### 定向变异

仅当关键条件的断言有效性仍有疑问时使用。选少量业务错误，例如放宽完成条件、删除身份校验或幂等检查；在隔离副本临时改变实现，确认相关测试因业务断言失败，再恢复。编译或导入错误不算断言有效。

存活变异先判断是否等价、不可达或确实缺断言，不追求全仓扫描或 100% 分数。已有确定性回归充分时停止，不再做同义实验。

### 属性与状态机

仅用于大量输入、状态或事件组合存在具体漏测风险的部分。独立定义业务不变量、前置条件和有效输入范围，不能由实现反推性质。例如未经授权不得跨用户写入，重复请求不得重复产生合同禁止的副作用。

设置时间或样例预算，检查核心断言确实执行，避免绝大多数输入被过滤。保留随机种子、事件记录，缩减并保存反例形成稳定回归。有限样例通过不能宣称所有组合正确；并发保障仍需相应并发证据。

### 表征、差分与契约

| 具体风险 | 方法与限制 |
| --- | --- |
| 不熟悉的旧实现将被替换 | 表征测试记录真实输入、输出、错误与副作用，标记已知错误；仅保护行为不变，不能证明业务正确。 |
| 新旧实现迁移或多套逻辑合并 | 使用相同输入、初始状态和受控事件序列做差分；只归一化合同允许变化的字段，逐项解释差异。新旧一致仍可能共同出错，需独立业务断言。 |
| 模块或服务接口变化 | 验证真实生产方和消费方的输入、输出、错误语义及适用版本。消费方自制 mock 不能单独证明生产方兼容；合同由主责任方验证，其他层只补独立风险。 |

### 受控故障与恢复

只在有明确恢复假设时注入故障，先指定位置、故障或事件顺序、影响范围、观察指标、停止条件和清理办法。复用隔离测试、重放或已有工具，实际触发相关断连重连、重复乱序、下游超时、队列饱和或部分提交，再检查最终状态、资源回收和副作用；正常路径通过、异常被捕获都不能证明恢复有效。

真实服务、共享资源或流量上的注入与压测须有适用授权；测试授权不自动包含这些操作。停止注入后确认恢复，未执行就报告未验证，不由一次恢复宣称能承受所有故障。
